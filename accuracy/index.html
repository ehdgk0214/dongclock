서버시간 추정의
의미와 한계

DongClock은 대상 웹 서버의 응답을 이용해 서버시간을 추정합니다. 숫자가 작아 보이는 것보다 관측 범위와 불확실성을 정직하게 보존하는 것을 우선합니다.

1. 무엇을 측정하는가

DongClock은 요청 전송 시각, 응답 헤더 수신 시각, HTTP Date를 함께 사용합니다. 한 응답을 정확한 한 점으로 취급하지 않고 가능한 시차 구간을 만들며, 여러 표본의 왕복 시간과 합의를 검토해 서버시간을 추정합니다. 검증된 기준은 단조 시계로 진행시켜 화면에 표시합니다.

2. HTTP Date의 해상도

HTTP Date는 일반적으로 1초 해상도입니다. 화면에 보이는 밀리초는 서버가 밀리초 timestamp를 보낸 결과가 아니라, 여러 구간의 교차와 단조 시계의 연속 진행으로 만든 추정 표시입니다.

3. 네트워크에서 알 수 없는 것

  • 왕복 시간은 관측할 수 있지만 요청과 응답 각각의 편도 지연을 독립적으로 관측할 수 없습니다.
  • 두 방향의 지연은 비대칭일 수 있으며, 왕복 시간의 절반이 정확한 편도 지연이라는 보장은 없습니다.
  • CDN, 프록시, 로드밸런서 또는 서로 다른 backend가 서로 다른 Date나 시계를 제공할 수 있습니다.
  • 대상 서버의 시계 자체가 UTC와 어긋나 있을 수 있습니다.

4. 불확실성·신뢰도 표시

앱의 추정 오차, uncertainty 또는 confidence는 표본 구간, 왕복 시간 편차, 구조적 일관성 등 내부 관측에 기반한 제품 지표입니다. confidence는 보정된 통계 확률을 뜻하지 않으며, 별도로 명시되지 않는 한 통계적 95% 신뢰구간을 자동으로 의미하지 않습니다. 또한 공통 방향의 네트워크 비대칭이나 서버 시계 편향은 내부 일관성만으로 검출하지 못할 수 있습니다.

5. Basic과 Pro

Basic은 낮은 요청량과 일반적인 표본 합의를 중심으로 동작합니다. Pro는 더 많은 초기 표본, 응답 경로·시간 특성 분리, cache 방어, boundary 관측과 보수적인 상태 승격을 추가로 사용합니다. 정밀 후보는 여러 조건을 통과했을 때만 표시 기준이 될 수 있으며 모순이 생기면 보수적으로 이전 방식으로 돌아갑니다.

이 추가 검증이 모든 환경에서 Pro가 Basic보다 항상 더 정확하다는 뜻은 아닙니다. 현재 benchmark도 일정한 “X ms 개선”을 보편적으로 입증하지 않습니다.

6. 고정 정확도와 성공 보장 없음

DongClock은 고정된 밀리초 정확도를 보장하지 않으며 원자시계, NTP 또는 PTP 계측기가 아닙니다.

티켓팅, 예약, 수강신청, 이벤트 참여 또는 구매의 성공도 보장하지 않습니다. 화면 표시 시점은 운영체제, WebView 프레임, IPC, 오디오·디스플레이 지연의 영향도 받습니다.

7. 서버 친화적 측정

DongClock은 지속적으로 공격적인 고빈도 polling을 피하고 측정 상태에 따라 동작을 조정합니다. 초기에는 기준 표본을 수집하고, 안정되면 요청 간격을 늘리며, 오류·제한 응답이나 연속 실패가 있으면 backoff합니다. 카운트다운 주변에는 요청을 잠시 멈추는 구간도 있습니다. Pro는 Basic보다 더 촘촘하게 확인하지만 역시 상태에 따라 조정됩니다.

HTTP 요청이 발생하므로 서버 부하가 전혀 없다고 말할 수는 없습니다. 사용자는 대상 서비스의 이용약관과 허용 범위를 확인해야 합니다.

ENGLISH

What a server-time
estimate means

DongClock estimates server time from the target web server’s responses. It prioritizes honest treatment of observable ranges and uncertainty over making a number look artificially precise.

1. What DongClock measures

DongClock combines request-send time, response-header receive time, and the HTTP Date value. It forms a possible offset interval rather than treating one response as an exact point, then evaluates round-trip timing and agreement across samples to estimate server time. A monotonic clock advances the accepted estimate for display.

2. HTTP Date resolution

HTTP Date normally has one-second resolution. Displayed milliseconds are not a millisecond timestamp supplied by the server; they are an estimate produced from overlapping intervals and monotonic progression.

3. What the network cannot reveal

  • Round-trip time is observable, but one-way delay cannot be independently observed for each direction.
  • Request and response delays may be asymmetric; half of RTT is not guaranteed to equal either one-way delay.
  • A CDN, proxy, load balancer, or different backend may provide a different Date value or clock.
  • The target server clock itself may be biased relative to UTC.

4. Uncertainty and confidence

Estimated error, uncertainty, and confidence are product indicators based on observed intervals, RTT variation, and structural consistency. Confidence is not a calibrated statistical probability and, unless explicitly stated otherwise, is not automatically a statistical 95% confidence interval. Shared network asymmetry or a common server-clock bias may remain invisible to internal consistency checks.

5. Basic and Pro

Basic focuses on lower request volume and standard interval agreement. Pro adds more initial samples, finer separation of response paths and timing behavior, stronger cache defenses, boundary observations, and conservative state promotion. A precision candidate can become the display source only after multiple validation conditions, with conservative fallback when evidence conflicts.

These checks do not mean Pro is always more accurate than Basic in every environment. Current benchmarks do not establish a universal “X ms more accurate” claim.

6. No fixed accuracy or outcome guarantee

DongClock does not guarantee fixed millisecond accuracy and is not an atomic clock, NTP client, or PTP instrument.

It does not guarantee success in ticketing, reservations, course registration, events, or purchases. Visible timing is also affected by the operating system, WebView frame scheduling, IPC, audio, and display latency.

7. Server-friendly measurement

DongClock avoids continuously aggressive high-frequency polling and adjusts measurement behavior according to state. It gathers a starting baseline, lengthens intervals after stability, and backs off after errors, rate limits, or repeated failures. It also pauses requests around countdown-sensitive periods. Pro measures more frequently than Basic but remains state-adaptive.

Because measurement still creates HTTP requests, DongClock cannot claim zero server load. Users must check and follow the target service’s terms and acceptable-use rules.
